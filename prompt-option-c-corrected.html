Claude Code Prompt — Option C: Direct Image Generation (corrected)
🧠 Opus — new serverless function + dual-path UI change + auto-regen on tweak
Read the full index.html and api/chat.js before touching anything. Do not make any changes until you have read both files completely. Pay particular attention to revealImagePrompt() and showImageTweakResult() — they are two separate functions that both render an image-prompt card with a build-row of buttons. The original/first prompt renders via revealImagePrompt; every subsequent tweak renders via showImageTweakResult. Both need the generate button.

This prompt implements Option C — direct image generation via fal.ai for the Flux vertical. Users who complete the image-gen intake and receive a Flux prompt will see a "generate image →" button that calls fal.ai and displays the result directly on nerlo.io. The button also appears in the tweak-result row, and when the user revises a prompt for which an image already exists, the new image regenerates automatically.

STEP 1 — Create api/image.js

Create a new Vercel serverless function at api/image.js. Model its structure exactly on api/chat.js — same CORS header pattern, same OPTIONS preflight handler, same try/catch error shape.

At the top of the file (outside the handler), export the runtime config so the function does not time out on Vercel's default 10s limit:

  export const config = { maxDuration: 60 };

The handler accepts POST requests with a JSON body: { prompt: string, ar: string }.

Map the ar value to an explicit { width, height } pair (Flux dev expects multiples of 16, ~1MP total):

  "1:1"  → { width: 1024, height: 1024 }
  "9:16" → { width: 768,  height: 1344 }
  "16:9" → { width: 1344, height: 768 }
  "2:3"  → { width: 832,  height: 1248 }
  anything else → 1:1 default

Call fal.ai with the FAL_API_KEY environment variable (already set in Vercel):

  POST https://fal.run/fal-ai/flux/dev
  Headers:
    Authorization: Key {FAL_API_KEY}
    Content-Type: application/json
  Body: { prompt, image_size: { width, height }, num_images: 1 }

The fal.ai response shape is { images: [{ url: "..." }] }. Extract images[0].url and return { url } with status 200. If no url is present in the response, return status 502 with { error: "no image returned" }. Wrap the fal.ai call in try/catch and return { error: err.message } with status 500 on failure. Do not modify api/chat.js.

STEP 2 — Add generateImage() helper to index.html

Add a new function called generateImage(prompt, ar, triggerBtn) to the script block in index.html. Place it immediately before the revealImagePrompt() function (currently at line ~1339).

This function does the following:

1. Set triggerBtn.textContent to "generating…" and triggerBtn.disabled = true.

2. Call /api/image via fetch (POST, Content-Type application/json, body JSON.stringify({ prompt, ar })). Parse the JSON response.

3. On success (response.ok AND data.url exists):
   a. Find any existing element with id="nerlo-image-card" and remove it — regeneration replaces the previous image.
   b. Create a div with className "brief-card" and id "nerlo-image-card". Set its inline style padding to 0 and overflow to hidden so the image fills it edge-to-edge with the card's border-radius.
   c. Create an img element with src=data.url, width 100%, display block, border-radius 13px, alt "generated image".
   d. Create a footer div with padding 0.85rem 1.1rem, display flex, justify-content flex-end.
   e. Inside the footer, create an anchor with textContent "download →", href "#", font-size 0.8rem, color var(--cream-dim), no text-decoration. Hover: var(--star); mouseout: var(--cream-dim).
   f. Wire the download anchor's click handler to fetch data.url, convert to a blob, create an object URL, programmatically click a hidden <a> with download="nerlo-image.jpg", then revokeObjectURL. This is required because fal.media is cross-origin and the native download attribute is ignored on cross-origin anchors. Wrap the fetch+blob in try/catch; on failure, fall back to window.open(data.url, '_blank').
   g. Append img and footer to the card, append card to innerEl, call scrollToBottom().
   h. Set triggerBtn.textContent to "regenerate →" and triggerBtn.disabled = false.

4. On failure (any error or missing url):
   a. Set triggerBtn.textContent to "generation failed — try again".
   b. Set triggerBtn.disabled = false.
   c. Do not render any card.

STEP 4 — Auto-regenerate on tweak when an image already exists

Still inside showImageTweakResult(revised), after the row has been appended to innerEl and scrollToBottom() has been called (i.e. at the very end of the function, after the existing tweakCount-warning block):

  if (imagePayload.tool === 'flux' && document.getElementById('nerlo-image-card')) {
    const genBtn = Array.from(row.querySelectorAll('.btn-build'))
      .find(b => b.textContent.startsWith('generate'));
    if (genBtn) genBtn.click();
  }

This uses the local `row` variable (already in scope) rather than re-querying the DOM, so there is no timing race. The condition fires only when (a) the tool is Flux and (b) a previous image card from a prior generation is still on screen. If the user tweaked the prompt without ever generating, no auto-gen happens — they still get the manual button.
